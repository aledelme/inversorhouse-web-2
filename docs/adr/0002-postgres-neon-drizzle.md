# 0002. Use PostgreSQL (Neon) with Drizzle ORM

- Status: accepted
- Date: 2026-10-18

## Context

v1 used MongoDB Atlas. v2 is a new product with no data migration. The domain is relational:
opportunities → promoter (user), municipality → province → community, interests (N:M), reports,
audit log. Search combines several filters with ordering and pagination. Hosting is Vercel.

## Decision

- PostgreSQL on **Neon** (free tier, Vercel integration, a database branch per Preview deployment).
- **Drizzle ORM** with the schema in `src/db/schema/*.ts` as the single source of truth and SQL
  migrations generated by drizzle-kit, committed in `src/db/migrations`.
- Standard `pg` driver everywhere (Docker locally, Neon in prod) with `attachDatabasePool` from
  `@vercel/functions`, so local and prod behave the same.
- Integrity lives in the database: FKs, enums, `CHECK` constraints (amounts > 0, min ≤ max…).
- Naming: camelCase in TypeScript, snake_case in SQL (`casing: "snake_case"`).
- Migrations run before `next build` on Vercel (`vercel.json` build command).

## Consequences

Typed queries inferred from the schema; reviewable SQL migrations (good for AI-authored changes).
Future options: full-text search (`tsvector`), PostGIS. `MONGO_DB_URI` is left unused.

## Alternatives considered

- MongoDB: fine for documents, but relational integrity and multi-filter search would live in code.
- Prisma: heavier runtime/codegen; Drizzle's schema-as-TS is easier for agents to read and edit.
